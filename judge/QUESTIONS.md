# Judge 标准问题集

供视觉判断模型（本地小型 VLM）对 `latest.jpg` 的每次画面变化提问。
所有问题沿用 jev 协议的三种题型，契约与云端 jev / 本地复刻实现互通。

设计依据：`剧本.txt`（触手小怪物剧本）、`AGENTS.md`（主持规则与两个既有子系统接口）、第 0 层画质门槛来自小 VLM 可靠性实测结论（欠曝下置信度不可靠）。

## 设计原则

1. **单帧可判定**。每个问题必须能凭一张静态帧 + state 文本回答；时序对比信息（上次摘要、帧差数据）由 state 携带，不要求模型记忆历史帧。
2. **游戏语言**。criteria 一律使用剧本术语（玩家、战衣、护甲、姿态、道具、镜头），不出现现实身体描述。
3. **概率化输出**。全部为 choice / score / noul 三类，带 confidence；置信度规则见文末，禁止裸采信 argmax。
4. **分层触发**。门控题每次帧差报警都问；感知题仅在门控判定"有变化"后追加；校验题仅在 LLM 输出 `intent.json` 后调用。
5. **批量合并**。同一层的问题打包进一次推理调用，减少往返。
6. **画质前置**。任何视觉判断前先跑画质自检（Q0），不合格直接跳过本轮，安静回退文字叙事。

## 题型约定

```json
{"type": "noul",   "instructions": "...", "criteria": {"true": "...", "false": "..."}}
{"type": "choice", "instructions": "...", "criteria": {"选项名": "描述", ...}}
{"type": "score",  "instructions": "...", "criteria": ["最低档", "...", "最高档"]}
```

返回统一携带：答案值、各选项概率（或 P(true)）、confidence、latency_ms。

## 第 0 层 · 画质自检

每次调用任何视觉判断前执行。失败则本轮全部跳过。

### Q0 `画面可用性` — noul

```
instructions: 这张游戏画面是否清晰可读，能够用于现场判断？
criteria:
  true  : 构图、亮度、清晰度足以辨认玩家的姿态、装备和桌面上道具
  false : 严重欠曝或过曝、剧烈运动模糊、镜头被遮挡、画面等于纯黑或纯色
```

- 阈值：P(true) < 0.5 → 本轮跳过视觉判断，state.json 记 `quality: "blocked"`。
- 依据：小型 VLM 在严重欠曝下准确率崩塌且置信度不可靠（AUROC≈0.5），必须上游拦截。

## 第 1 层 · 门控（LLM 调用时机）

帧差层报警后调用。回答"值不值得叫醒 5-30 秒的大模型"。

### Q1 `是否唤醒主持人` — noul 【门控主开关】

```
instructions: 与 state 中的上一帧摘要相比，当前画面是否出现了剧情级变化，需要主持人大模型介入？
criteria:
  true  : 出现了值得推进剧情的变化——姿态明显改变、道具被拿起/放下/移走、
          镜头转向新区域、护甲或战衣状态可见地改变、出现此前不在画面中的新物体
  false : 画面与上次实质相同，或仅有微小调整（手指微动、光影抖动、镜头呼吸）
```

- 阈值：P(true) ≥ 0.6 唤醒（门控侧宁可多唤醒，漏报代价 = 剧情失明）。
- 为抑制连发：触发后进入冷却窗口（默认 20s），窗口内同类变化不再唤醒，但变化仍记入 state 历史。

### Q2 `变化幅度` — score 【唤醒紧急度】

```
instructions: 相比上一帧摘要，当前画面变化有多剧烈？
criteria: ["无变化", "微小调整", "明显动作", "剧烈变化"]
```

- 输出作为唤醒 prompt 里的紧急度标签：≥2 才唤醒；3 时唤醒 prompt 标注 `urgent`。
- 用法：与 Q1 交叉验证——Q1 说 true 但 Q2 ≤1 视为噪声，丢弃。

### Q3 `变化类别` — choice 【唤醒时的上下文路由】

```
instructions: 本次变化主要属于哪一类？
criteria:
  姿态变化 : 玩家身体的姿势、朝向、位置发生了可见改变
  道具变化 : 桌面或手中的物品被拿起、放下、移走、翻面或增减
  镜头移动 : 视角转向了不同区域，或镜头推拉改变了取景范围
  装备状态 : 战衣、护甲、披风的穿戴状态或表面状态出现可见改变
  多类并发 : 以上不止一类同时发生
```

- 只在 Q1 触发后作答，结果写入 state.json 的 `changes`，供唤醒 prompt 直接引用。

## 第 2 层 · 现场感知（LLM 唤醒后，可选增强）

仅在门控触发、且 LLM 将要读图时顺带执行，为 digest 提供结构化细节。
**跳过条件**：LLM 本轮决定读原图，则本层可省略（原图信息量 > 感知摘要）。

### Q4 `玩家姿态` — choice

```
instructions: 画面中玩家当前的总体姿态最接近哪一种？
criteria:
  端坐整理 : 稳定坐着，手部在做整理、翻找、摆弄类小动作
  后仰戒备 : 身体向后撤离桌面或镜头，呈防备姿态
  前倾专注 : 身体前倾靠近镜头或某件物品，注意力集中
  侧身隐藏 : 身体转向侧面，部分躯体移出画面或被遮挡
  无法判断 : 姿态被遮挡、出画或画质不足
```

### Q5 `手部占用` — choice

```
instructions: 画面中玩家的双手此刻主要在做什么？
criteria:
  双手可见空闲 : 双手都在画面内且未持握或操作任何东西
  持有物品     : 至少一只手握着或托着某件道具
  操作动作中   : 正在翻找、穿戴、拉扯衣物或护甲
  手部不可见   : 双手均不在画面内或完全被遮挡
```

### Q6 `视野焦点` — choice

```
instructions: 当前镜头主要对准什么区域？
criteria:
  上半身近景 : 胸部以上占画面主体
  全身中景   : 可见从头到腰腹或大腿的完整上半身轮廓
  桌面道具   : 画面主体是桌面上的物品而非人
  环境空镜   : 既无人物主体也无道具，拍的是房间环境
  特写局部   : 极近距离的单一物件或身体局部
```

### Q7 `道具清点` — noul

```
instructions: 与 state 中的桌面道具基线相比，画面中的道具数量或位置是否发生了改变？
criteria:
  true  : 有道具消失、出现、被拿起或位置明显移动
  false : 道具与基线一致
```

## 第 3 层 · 输出校验（LLM 输出 intent.json 后执行）

纯本地规则为主（数值边界、冷却、冲突互斥），以下问题仅在需要语义仲裁时调用。
调用时 **不传图**，state 为 intent 摘要 + 当前反馈状态 + 最近校验历史。

### Q8 `反馈强度越界` — choice

```
instructions: 结合剧本允许的强度区间和当前正在运行的反馈状态，LLM 请求的这次反馈应如何处置？
criteria:
  放行 : 强度与时长均在允许区间内，且与正在运行的效果不冲突
  降级 : 超出区间但可安全地降到相邻档位执行
  拒绝 : 触碰硬边界（超上限、冷却未过、与运行中效果冲突、非有界持续请求）
```

- 处置规则：放行 → 写 feedback/event.json；降级 → 写降级后的事件并回写 intent.json 标注；拒绝 → 丢弃，intent 标注 `rejected`。
- **数值硬边界不问模型**：`set > 100`、`hit ≤ 0`、时长缺失等在规则层直接拒绝，不消耗模型调用。

### Q9 `玩家承受状态` — score

```
instructions: 基于画面和最近的反应历史，玩家当前对正在进行的反馈的承受状态如何？
criteria: ["轻松无感", "略有紧绷", "明显不适但可承受", "接近极限", "已超限或强烈抗拒"]
```

- 只在反馈运行中调用；score ≥ 3 时强制进入衰减（下一事件强度减半），score ≥ 4 时直接 STOP 并唤醒 LLM。

### Q10 `玩家回应类型` — choice 【反应闭环】

```
instructions: 针对刚刚发生的剧情与反馈，玩家画面呈现的反应最接近哪一类？
criteria:
  配合继续 : 姿态放松或维持，无回避迹象
  轻微抵抗 : 局部收紧、遮挡、后撤但未离开
  明确回避 : 大幅度后撤、转身、用手格挡、移出道具
  中断请求 : 画面中出现手势、纸条、屏幕等明确暂停/停止信号
  不可判断 : 画质或构图不足以读出反应
```

- `中断请求` P ≥ 0.7 → 立即 STOP 所有反馈，并唤醒 LLM（最高优先级）。
- `明确回避` → 下一轮 intent 中 LLM 应降低强度；连续两次 → 强制冷却。

---

## 置信度与降级规则

| 场景 | confidence < 0.6 时 |
|---|---|
| 门控 Q1 | **宁可唤醒**（漏报代价高于误报） |
| 门控 Q2/Q3 | 结果标 `low_conf`，只记录不参与交叉验证 |
| 感知 Q4-Q7 | 结果标 `low_conf`，digest 中注明"不确定" |
| 校验 Q8 | **宁可拒绝**（越界宁可降级，不确定就不发） |
| 校验 Q9/Q10 | 按保守方向处置（视为更高档位） |

## 云端兜底（可选，默认关闭）

本地 VLM 不可用或连续 3 次 low_conf 时，可转发同一问题到 jev 云端。
默认仅传文本 state；传图必须由玩家在会话中明确授权，且授权仅本次有效。

## 打包调用示例

门控层一次推理问三题（Q1+Q2+Q3）：

```json
{
  "state": "上一帧摘要：玩家端坐整理，桌面有[纸条x2, 骰子, 饰品]。10秒内帧差区域：手部/桌面左上。",
  "images": ["<latest.jpg base64>"],
  "questions": {
    "是否唤醒主持人": { "...": "Q1 定义" },
    "变化幅度":       { "...": "Q2 定义" },
    "变化类别":       { "...": "Q3 定义" }
  }
}
```

输出落 `judge/state.json`：

```json
{
  "updated_at": "2026-10-02T12:00:00+08:00",
  "frame_seen": 4821,
  "quality": "ok",
  "motion": 0.13,
  "gate": {"wake": true, "urgency": 2, "urgency_low_conf": false, "categories": ["道具变化"]},
  "perception": {"pose": "前倾专注", "hands": "持有物品", "focus": "桌面道具", "props_changed": true},
  "digest": "玩家前倾拿起桌面左侧纸条，姿态由端坐转为专注；道具基线变化：纸条-1",
  "history": ["<最近N条压缩记录>"]
}
```
